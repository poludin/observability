# Incident Post-Mortem: Каскадный сбой Frontend при отказе CartService

**Дата:** 25 Августа 2026
**Авторы:** Александр Полудин
**Статус:** Resolved

## 1. Резюме (Summary)
Полный отказ сервиса корзины (`cartservice`) привел к каскадному сбою фронтенда (`frontend`), сделав невозможным просмотр каталога и оформление заказов. Инцидент был искусственно вызван в рамках Chaos Engineering-эксперимента для проверки системы алертинга.

## 2. Влияние (Impact)
* **Пользователи:** 100% пользователей получали ошибку HTTP 500 (Internal Server Error) при попытке взаимодействия с магазином.
* **Длительность:** ~15 минут.
* **Служба поддержки:** Всплеск обращений не зафиксирован (контролируемый сбой).

## 3. Хронология (Timeline)
* **T+0:** Искусственное масштабирование `cartservice` до 0 реплик.
* **T+1m:** Prometheus зафиксировал рост RED-метрики ошибок (status_code="STATUS_CODE_ERROR"), сгенерированной Alloy `spanmetrics`. Алерт `HighErrorRate` перешел в PENDING.
* **T+2m:** Уровень ошибок >5% подтвержден. Алерт перешел в FIRING, сработала маршрутизация Alertmanager.
* **T+10m:** Начало восстановительных работ, запуск новых подов `cartservice`.
* **T+12m:** Трафик нормализовался, алерты перешли в статус RESOLVED.

## 4. Корневая причина (Root Cause)
Отсутствие паттерна **Circuit Breaker** во фронтенде. Приложение осуществляет жесткий синхронный gRPC-вызов к `cartservice` (ошибка `dial tcp connection refused`) при рендеринге любой страницы. Недоступность некритичного узла (корзины) полностью блокирует рендеринг критичного функционала (витрины).

## 5. Action Items (План действий)
1. **[Архитектура]** Внедрить паттерн Circuit Breaker / Fallback на gRPC-вызовы из фронтенда. При недоступности `cartservice` возвращать пустую корзину.
2. **[Инфраструктура]** Внедрить HPA (Horizontal Pod Autoscaler) для `cartservice`.
3. **[Мониторинг]** Интегрировать Alertmanager с Telegram-каналом дежурной смены (в процессе).
